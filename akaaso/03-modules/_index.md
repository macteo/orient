# Level 3 — Modules

**Status:** Signed off 2026-09-05

Level 2 fixed a static site with no server, so this level is almost
entirely about content: how four kinds of card are extracted from two
source documents and two artwork sets, what the data looks like, and what
runs where. The founder's three wishes of 2026-09-05 — full description
rows combining symbols, single-symbol cards with their description and the
worked examples, ISOM terrain cards — became three pipelines and one shared
model. A cell-cropping probe on the control-descriptions PDF succeeded the
same day, so nothing here is speculative.

## Level Review

- **Summary of everything decided:** four modules cut by where code runs —
  extraction by hand on the curator's Mac, deck assembly at build, playing
  and navigation in the browser. One data model whose load-bearing field is
  *verbatim versus generated*. Four content pipelines: pictograms from the
  Purple Pen SVGs with text from the Italian IOF booklet; full description
  rows, nine official and two hundred generated by a prefix-stable seeded
  script with a compatibility table; worked examples cropped from the
  booklet's §Esempi by detected table rules, map and sketch in front, row
  and sentence behind; ISOM symbols rendered from the IOF's own per-symbol
  files on white with their printed annotations, text from the Italian
  specification. Swift and PDFKit for extraction, TypeScript for parsing,
  checks and the site; output committed, CI checks only; no providers, no
  events. One licence register generating the attribution page; the [S3]
  risk re-confirmed for the wider scope; git is the backup.
- **Tensions surfaced between decisions:** the wider use of [S3] against
  the risk accepted at Level 1 — surfaced in 008, re-confirmed by the
  founder, recorded on T1. The founder's literal "extract from the PDF"
  against the cleaner sources found later — resolved per deck: the PDF is
  cropped where it is the only source (examples, fallback pictograms) and
  the vector sets are used where they exist.
- **Improvements applied to the level as a whole:** every pipeline is
  deterministic and its check is "re-run and diff", so the four checks
  share one mechanism; the row generator became prefix-stable at the
  founder's request so the deck can grow without churning; the model
  gained `origine` so no generated text can pass as official.
- **What Level 4 inherits:** four decks with slugs to fix, a run that is one
  stateful screen, a row-rendering component that must match page 3, a
  contact-sheet review step, and a per-example `nascondi` flag to specify.
- **Sign-off:** founder, 2026-09-05 — "ok, signoff su livello 3 e feature".
