# P1-MAZZI-BUILD-decks-e-pagine — Assemble the four decks and emit the thirteen pages at build

## Objective

Replace the `scripts/build-mazzi.ts` stub: read `content/`, produce one deck
JSON per deck (cards, sections with counts, distractor pools, stable ids), emit
the pictogram sprite module, and generate the thirteen HTML pages from
templates with the deck JSON inlined, so `vite build` produces the whole site
at the registry's paths. Spec: `akaaso/04-features/006-mazzi-a-build.md`,
`akaaso/04-features/_routes.md`, `akaaso/02-architecture/007-route-conventions.md`.

---

## Specification

### Deliverables

- `scripts/build-mazzi.ts` → `.generated/mazzi/<deck>.json` (`MazzoBuild`),
  `.generated/pages/<deck>/{flashcard,quiz,risultati}/index.html` ×4 decks,
  `.generated/pages/fonti/index.html`, and rewrites the root `index.html`
  from `src/sito/templates/home.html` with the deck summaries inlined.
  Vite's config already globs `.generated/pages/**/index.html`; make sure the
  emitted pages live at those paths and that `vite build` copies them to
  `dist/<deck>/flashcard/index.html` etc. (use `build.rollupOptions.input`
  keys that preserve the folder path; adjust `vite.config.ts` only for this).
- `src/sito/templates/{home,run,risultati,fonti}.html` — Preline shell (header,
  main, footer), `<script type="application/json" id="mazzo">…</script>` for the
  deck data, `<script type="module" src="/src/pages/<page>.ts">`; page entries
  `src/pages/{home,flashcard,quiz,risultati,fonti}.ts` created as **stubs that
  import `../styles.css`, `../sito/preline.ts` and render the page title** —
  the UI tasks fill them (wiring lives here, implementation there).
- `src/allenamento/facce/sprite.generated.ts` — every pictogram SVG's inner
  markup keyed by `<rif>[<DIR>]` (from `content/artwork/descrizioni-punti/`),
  generated by `scripts/lib/sprite.ts`.
- `src/mazzi/assembla.ts` — pure deck assembly (`assemblaMazzo(contenuti, sezioni)`)
  with Vitest tests; `build-mazzi.ts` is the thin I/O wrapper.
- Base path: every emitted link uses `import.meta.env.BASE_URL` or a relative
  path; templates carry `<base href>`-free relative asset paths.

### Deck definitions (F-006 table)

`descrizioni-simboli` (simbolo), `descrizioni-complete` (riga: `ufficiali`
first, generated rows under the D family of their D cell), `esempi` (esempio,
sections via `esempi/sezioni.json` page mapping), `isom` (simbolo-isom).
`nascondi: true` excludes a card everywhere. Distractor pools: per section, and
per column for control descriptions.

---

## Done Criteria

1. `VITE_BASE=/orient/ npm run build` emits exactly thirteen pages at the
   registry paths under `dist/` plus assets; `ls dist/*/quiz/index.html | wc -l`
   prints 4.
2. Each deck JSON contains every non-hidden content entry once; the total per
   deck equals the sum of its section counts (unit test on `assemblaMazzo`
   with a content fixture; integration assertion in `check:dist` optional).
3. `descrizioni-complete` lists the nine official rows first under
   `ufficiali` and every generated row under exactly one D family.
4. Building twice from the same content yields identical `dist/` (excluding
   hashed asset names — compare emitted HTML and JSON).
5. `e2e:smoke` extended: every emitted page loads on `vite preview` with no
   console error and shows its title.
6. Every criterion names an observable effect, not a file that exists.
